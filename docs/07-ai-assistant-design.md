# ۷. طراحی دستیار هوشمند

## ۷.۱ اصل اعتماد
مدل زبانی **پیشنهاددهنده** است، نه تصمیم‌گیرنده. او فقط متن را به یک ساختار پیشنهادی تبدیل می‌کند. بک‌اند همه‌چیز را دوباره اعتبارسنجی می‌کند و بدون تأیید کاربر هیچ عملیات نوشتنی اجرا نمی‌شود.

## ۷.۲ خط لوله (Pipeline)

1. **ورودی**: متن، یا صدا ⇒ `faster-whisper` ⇒ متن قابل ویرایش توسط کاربر ⇒ ارسال.
2. **نرمال‌سازی قطعی**: ارقام فارسی/عربی به لاتین، `ي→ی`، `ك→ک`، حذف نیم‌فاصله‌های اضافی، تبدیل جداکننده‌ها.
3. **تفسیر توسط LLM** با خروجی ساخت‌یافته (JSON Schema). ورودی مدل: متن فرمان + فهرست **نام** حساب‌ها، اشخاص و دسته‌ها. موجودی و مبالغ ذخیره‌شده ارسال نمی‌شود.
4. **استخراج عبارت‌های خام**: مدل `amount_text`، `date_text` و `party_text` را همان‌طور که در متن بوده برمی‌گرداند.
5. **تبدیل قطعی توسط بک‌اند**:
   - مبلغ: `Persian amount parser` («۲۰ میلیون تومان»، «دو و نیم میلیون»، «۱۲۰۰۰۰۰ ریال») ⇒ ریال صحیح.
   - تاریخ: `Persian date parser` («۲۵ آذر ۱۴۰۵»، «۱۴۰۵/۹/۲۵»، «فردا»، «آخر این ماه»، «۳ روز دیگه») ⇒ تاریخ میلادی؛ مرجع «امروز» از سرور (Asia/Tehran).
   - شخص/حساب/دسته: تطبیق دقیق، سپس شباهت رشته‌ای (آستانه). چند گزینه نزدیک ⇒ سؤال تکمیلی با فهرست گزینه‌ها. نبود تطبیق برای شخص ⇒ پیشنهاد ساخت شخص جدید در همان پیش‌نمایش.
6. **اعتبارسنجی** با همان Schemaهای Pydantic که API عمومی استفاده می‌کند.
7. **پیش‌نمایش** (`awaiting_confirmation`) با ذخیره `payload` و `payload_hash`.
8. **تأیید** ⇒ اجرا از طریق `LedgerService`/`DebtService`/`ChequeService` با `Idempotency-Key`.

## ۷.۳ قصدهای پشتیبانی‌شده (نسخه ۱.۰)

| intent | پارامترها | الزامی |
|---|---|---|
| `create_income` | مبلغ، دسته، حساب، تاریخ، توضیح | مبلغ، دسته، حساب |
| `create_expense` | مثل بالا | مبلغ، دسته، حساب |
| `create_transfer` | مبلغ، حساب مبدأ، حساب مقصد، تاریخ | همه |
| `create_debt` | جهت، شخص، مبلغ، سررسید | جهت، شخص، مبلغ |
| `settle_debt` | شخص یا بدهی، مبلغ (یا «کامل»)، حساب، تاریخ | شخص، حساب |
| `create_cheque` | جهت، شخص، مبلغ، سررسید، شماره، بانک | جهت، شخص، مبلغ، سررسید |
| `update_cheque_status` | چک، وضعیت جدید، حساب (برای وصول) | چک، وضعیت |
| `query` | پرسش آزاد درباره وضعیت مالی | — |
| `unknown` | — | پاسخ «متوجه نشدم» + مثال |

فیلد الزامی خالی ⇒ `needs_clarification` با **یک** سؤال کوتاه در هر نوبت.

### نمونه‌ها

| فرمان | رفتار |
|---|---|
| «یک چک ۲۰ میلیون تومانی برای شرکت میهن به تاریخ ۲۵ آذر ۱۴۰۵ ثبت کن.» | `create_cheque`، جهت: صادره (چون «برای» شرکت)، مبلغ `200,000,000` ریال، سررسید `2026-12-16`. اگر جهت مبهم بود از کاربر می‌پرسد. ⇒ پیش‌نمایش |
| «۵ میلیون از آقای محمدی گرفتم» | مبهم (وصول مطالبه یا درآمد؟) ⇒ سؤال تکمیلی |
| «هزینه برق ۳۵۰ هزار تومن» | حساب خالی ⇒ «از کدام حساب؟» با فهرست حساب‌ها |

## ۷.۴ پرسش و پاسخ
مدل فقط **ابزارهای فقط‌خواندنی** را فراخوانی می‌کند: `get_balance`، `get_obligations`، `get_monthly_report`، `get_cheques_due`، `get_debts_summary`. اعداد از پاسخ ابزار می‌آیند. مدل مجاز نیست عددی را خودش حدس بزند یا محاسبه کند.
- مثال: «تا آخر ماه چقدر پول برای پرداخت بدهی‌ها نیاز دارم؟» ⇒ ابزار `get_obligations(until=آخر ماه شمسی)` ⇒ پاسخ متنی با همان عدد و فهرست اقلام.
- پاسخ شامل «منبع محاسبه» (لینک به گزارش) است تا کاربر بتواند بررسی کند.

## ۷.۵ ایمنی
- ورودی کاربر و نام‌های ذخیره‌شده در پرامپت همیشه به‌عنوان **داده** (با جداکننده مشخص) قرار می‌گیرند.
- خروجی نامعتبر یا خارج از Schema ⇒ یک تلاش مجدد و سپس پیام خطای مهربان.
- هیچ ابزار نوشتنی به مدل داده نمی‌شود.
- اجرای عملیات فقط با `confirm` کاربر و همان `payload_hash`.
- نرخ‌محدودیت و سهمیه روزانه.
- ثبت `raw_text`، `intent`، `payload` برای ردیابی (بدون ثبت کلید API).

## ۷.۶ اینترفیس Provider

```python
class LLMProvider(Protocol):
    async def parse_command(self, text: str, context: ParseContext) -> ParsedCommand: ...
    async def answer_with_tools(self, question: str, tools: list[ReadOnlyTool]) -> Answer: ...

class SpeechProvider(Protocol):
    async def transcribe(self, audio: bytes, mime: str) -> Transcript: ...
```
پیاده‌سازی‌ها: `ExternalLLMProvider`، `FakeLLMProvider` (برای تست و CI، خروجی از پیش تعیین‌شده)، و در صورت نیاز `LocalLLMProvider`.

## ۷.۶.۱ تصمیم‌های باز که در فاز ۵ بسته می‌شود
1. سرویس LLM مشخص (نیاز به تأیید دسترسی شبکه سرور و هزینه)
2. اندازه مدل Whisper (`large-v3` به GPU نیاز دارد؛ روی CPU احتمالاً `medium`/`small` با کوانتیزه int8). **تصمیم بر اساس اندازه‌گیری واقعی دقت و تأخیر روی نمونه صدای فارسی.**
3. آستانه شباهت نام‌ها

## ۷.۷ تست
- مجموعه ثابت ≥ ۶۰ فرمان فارسی (طبیعی، محاوره‌ای، ناقص، مبهم) با خروجی مورد انتظار؛ در CI با `FakeLLMProvider` برای تست خط لوله و پارسرهای قطعی.
- تست پارسر مبلغ و تاریخ به‌صورت مستقل از LLM (جدول ورودی/خروجی + تست خاصیتی).
- تست «بدون تأیید هیچ ردیفی ساخته نمی‌شود» و «پیش‌نمایش منقضی قابل تأیید نیست».
- تست دستی/اندازه‌گیری کیفیت LLM واقعی و Whisper فقط در فاز ۵ و با گزارش صادقانه نتیجه.
